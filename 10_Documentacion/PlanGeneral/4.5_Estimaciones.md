# 4.5 Estimaciones de Costo y Esfuerzo

## Introducción

La estimación de esfuerzo y costo es una actividad crítica en la planificación de
proyectos de software. Cohn (2005) señala que estimar en proyectos de software
es inherentemente difícil debido a la naturaleza intangible del producto, la
incertidumbre en los requisitos y la variabilidad en la productividad del equipo.
Sin embargo, contar con estimaciones razonables permite planificar el trabajo,
gestionar expectativas y tomar decisiones informadas sobre el alcance del proyecto.

Para TrackVer A&A se utiliza el método de **Puntos de Historia (Story Points)**,
ampliamente adoptado en metodologías ágiles, que permite estimar el esfuerzo
relativo de cada elemento del backlog en función de su complejidad, cantidad de
trabajo e incertidumbre, sin vincular la estimación directamente a unidades de
tiempo (Cohn, 2005).

---

## Escala de Estimación

Se utiliza la secuencia de Fibonacci modificada, recomendada por Cohn (2005)
para la estimación con Story Points, ya que refleja la incertidumbre creciente
en elementos más complejos:

| Story Points | Significado |
|:------------:|-------------|
| 1 | Tarea trivial, completamente conocida, sin incertidumbre |
| 2 | Tarea simple con mínima incertidumbre |
| 3 | Tarea simple con alguna complejidad |
| 5 | Tarea de complejidad moderada, bien entendida |
| 8 | Tarea compleja con algo de incertidumbre |
| 13 | Tarea muy compleja o con alta incertidumbre |
| 21 | Tarea excesivamente grande, debe dividirse |

## Velocidad del Equipo y Duración Estimada

Considerando que el equipo de desarrollo es unipersonal y que el tiempo disponible
para el proyecto es parcial (combinado con actividades académicas), se estima
una velocidad de **13 a 17 Story Points por sprint**, con sprints de 3 semanas.

| Escenario | Velocidad (SP/sprint) | Sprints estimados | Duración total |
|-----------|:---------------------:|:-----------------:|:--------------:|
| Pesimista | 13 SP/sprint | 6 sprints | 18 semanas |
| Esperado | 15 SP/sprint | 5 sprints | 15 semanas |
| Optimista | 17 SP/sprint | 4 sprints | 12 semanas |

El escenario **esperado** de 5 sprints (15 semanas) se adopta como línea base
para la planeación del cronograma.

## Estimación de Costos

Al tratarse de un proyecto académico desarrollado de forma individual, los costos
se clasifican en tres categorías:

### Costos de Herramientas y Software

| Herramienta | Costo |
|-------------|-------|
| Java 17 (JDK) | $0 — Open source |
| Apache Maven | $0 — Open source |
| SQLite + sqlite-jdbc | $0 — Open source |
| Leaflet.js | $0 — Open source |
| Visual Studio Code | $0 — Gratuito |
| GitHub (repositorio público) | $0 — Gratuito |
| **Total herramientas** | **$0** |

### Costo de Desarrollo (Costo de Oportunidad)

Considerando una tarifa de referencia para desarrolladores Junior en México
de aproximadamente **$100 MXN/hora** (IMCO, 2023):

| Concepto | Horas | Costo estimado (MXN) |
|----------|:-----:|:--------------------:|
| Desarrollo de software | 253 hrs | $25,300 |
| **Total desarrollo** | **253 hrs** | **$25,300 MXN** |

### Costos de Infraestructura (Fase de Producción)

Estos costos aplican únicamente cuando el sistema sea desplegado en un
entorno de producción real, fuera del alcance de esta etapa académica:

| Concepto | Costo mensual estimado (MXN) |
|----------|:----------------------------:|
| VPS básico (servidor de hospedaje) | ~$300 — $500 |
| Dominio web | ~$150/año (~$12/mes) |
| **Total infraestructura** | **~$312 — $512/mes** |
