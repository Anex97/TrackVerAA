# 4.1 Definición y Alcance del Producto de Software

## Definición del Producto

TrackVer A&A es una aplicación web para la gestión y monitoreo de flotillas
vehiculares. El nombre proviene de "Track" (rastrear en inglés) y "Ver"
(abreviatura de Veracruz, lugar de origen del proyecto). El sistema surge como
respuesta a la dependencia tecnológica que enfrentan los técnicos instaladores
de GPS que dependen de plataformas privadas de terceros para activar y monitorear
los dispositivos, generando esperas de hasta una hora por unidad. Según Pressman
y Maxim (2020), un producto de software exitoso debe estar alineado con las
necesidades reales del cliente y ser técnicamente viable; TrackVer A&A cumple
ambas condiciones al partir de un problema real documentado y utilizar tecnologías
maduras y de código abierto.

---

## Alcance del Sistema

El alcance de TrackVer A&A delimita el conjunto de funcionalidades, componentes
tecnológicos e integraciones de hardware que serán desarrollados e implementados
durante el periodo académico del proyecto. Su definición parte del problema
identificado — la dependencia de plataformas externas por parte de técnicos
instaladores de GPS — y se extiende hasta cubrir una solución funcional
completa, que incluye tanto el software web como la interconexión real con
hardware físico mediante un microcontrolador ESP32 y un módulo GPS. Las
funcionalidades aquí descritas constituyen el compromiso mínimo entregable al
término del proyecto; cualquier elemento no mencionado explícitamente se
considera fuera del alcance de esta versión.

### Lo que el sistema INCLUYE

El sistema TrackVer A&A comprende el desarrollo e implementación de los siguientes
módulos funcionales:

| Módulo | Descripción detallada |
|--------|----------------------|
| **Autenticación y roles** | Sistema de inicio de sesión con credenciales (usuario y contraseña cifrada), validación contra base de datos y redirección al panel correspondiente según el rol asignado: Administrador, Auditor o Usuario. Incluye bloqueo por intentos fallidos. |
| **Gestión de usuarios** | Panel exclusivo del Administrador para crear, editar, desactivar y eliminar cuentas de usuario. Permite asignar roles y gestionar credenciales de acceso. |
| **Gestión de dispositivos GPS** | Registro de dispositivos GPS en el sistema con datos como identificador único, modelo, número de serie y vehículo asociado. Permite activar, desactivar y reasignar dispositivos. |
| **Visualización en mapa en tiempo real** | Integración con Leaflet.js para mostrar en un mapa interactivo la última posición conocida de cada dispositivo registrado. Los marcadores se actualizan periódicamente sin recargar la página. |
| **Historial de posiciones** | Almacenamiento persistente de todas las posiciones GPS recibidas con marca de tiempo. Permite consultar el recorrido de un vehículo específico en un rango de fechas seleccionado, visualizando la trayectoria sobre el mapa. |
| **Geocercas** | Herramienta para definir zonas geográficas de interés (polígonos o radios) sobre el mapa, asociarlas a uno o varios vehículos y configurar el tipo de alerta (entrada, salida o ambas). |
| **Alertas automáticas** | Generación y registro automático de alertas cuando un vehículo viola los límites de una geocerca configurada. Las alertas se almacenan con detalle de unidad, zona, tipo de evento y timestamp. |
| **Comandos remotos** | Módulo para el envío de comandos a distancia a los dispositivos GPS, incluyendo el apagado remoto del vehículo. Cada comando ejecutado queda registrado con el usuario que lo solicitó y la marca de tiempo. |
| **Auditoría del sistema** | Registro de las acciones relevantes realizadas por los usuarios dentro del sistema, incluyendo inicios de sesión, modificaciones a datos y comandos ejecutados, para trazabilidad y seguridad. |
| **Panel de administración** | Interfaz centralizada desde la cual el Administrador gestiona la configuración general del sistema, incluyendo usuarios, dispositivos y parámetros operativos. |
| **Integración con hardware ESP32 + módulo GPS** | Desarrollo del firmware embebido en un microcontrolador ESP32 conectado a un módulo GPS (e.g., NEO-6M). El ESP32 lee las tramas NMEA del módulo GPS, extrae latitud, longitud y timestamp, y envía la posición al servidor Java vía HTTP (endpoint REST) a través de la red Wi-Fi. Esto constituye la capa física de captura de datos y valida la interconexión real entre hardware y aplicación web. |

### Lo que el sistema NO INCLUYE en esta etapa

Las siguientes funcionalidades quedan **fuera del alcance** de la versión actual,
ya sea por limitaciones técnicas del entorno académico, por estar planificadas
para versiones futuras o por no ser necesarias en el contexto del cliente objetivo
en esta etapa:

| Exclusión | Razón |
|-----------|-------|
| Aplicación móvil nativa (iOS / Android) | Planificada para una versión futura; la interfaz web responsiva cubre la necesidad inmediata |
| Facturación y cobro automatizado (modelo SaaS) | Fuera del alcance académico; se implementará en la fase de comercialización |
| Integración con sistemas ERP o plataformas de logística | No requerido por el cliente en esta etapa |
| Soporte multilenguaje (internacionalización) | El mercado objetivo es hispanohablante; se evaluará en versiones futuras |
| Notificaciones push o por correo electrónico | Las alertas se visualizan en la interfaz del sistema; las notificaciones externas se considerarán en iteraciones posteriores |
| Reportes exportables en PDF o Excel | Funcionalidad deseable pero no crítica para el cliente en esta fase |

## Descripción Funcional del Sistema

Esta sección describe el flujo de uso del sistema desde la perspectiva de cada
rol, con el fin de ilustrar de forma concreta cómo TrackVer A&A resuelve el
problema identificado.

### Flujo del Administrador

El Administrador accede al sistema con sus credenciales y es redirigido al panel
de administración. Desde ahí puede registrar nuevos usuarios (técnicos o clientes),
asignarles un rol y gestionar los dispositivos GPS del inventario. Cuando un
técnico instala un nuevo dispositivo en campo, el Administrador lo registra en el
sistema con el identificador del equipo y lo asocia al vehículo correspondiente,
dejándolo activo para recibir posiciones. Este proceso, que en el esquema actual
con plataformas de terceros tarda hasta una hora esperando respuesta de soporte
externo, se reduce con TrackVer A&A a una operación de minutos realizada de forma
autónoma.

### Flujo del Auditor (Técnico Instalador)

El Auditor accede al sistema y puede visualizar en el mapa el estado de todos los
dispositivos bajo su supervisión. Puede consultar el historial de recorridos de
cualquier unidad, configurar geocercas para delimitar zonas de operación y, en
caso de emergencia o robo, ejecutar el comando de apagado remoto del vehículo
directamente desde la interfaz, sin necesidad de contactar a un equipo de soporte
externo. Todas las acciones quedan registradas en el módulo de auditoría.

### Flujo del Usuario (Propietario de Flota)

El Usuario accede al sistema y visualiza en tiempo real la posición de sus
vehículos sobre el mapa. Puede consultar el historial de recorridos para
verificar rutas tomadas, revisar las alertas generadas por violaciones de
geocerca y conocer el estado operativo de cada unidad. Su acceso está limitado
a la información de su flota, garantizando la privacidad entre clientes.

## Contexto Tecnológico

TrackVer A&A se desarrolla sobre una arquitectura de dos capas claramente
diferenciadas, siguiendo el principio de separación de responsabilidades:

### Backend

| Componente | Tecnología | Justificación |
|------------|-----------|---------------|
| Microcontrolador | ESP32 | Microcontrolador de bajo costo con Wi-Fi integrado, ampliamente utilizado en proyectos IoT. Permite conectar el módulo GPS y enviar datos al servidor sin hardware especializado adicional. |
| Módulo GPS | NEO-6M (u-blox) | Módulo GPS de bajo costo con salida NMEA estándar, compatible con el ESP32 vía comunicación serial (UART). Proporciona latitud, longitud, altitud y timestamp con precisión suficiente para rastreo vehicular. |
| Firmware ESP32 | Arduino framework (C++) | Lenguaje y framework estándar para programación del ESP32. Permite lectura del puerto serial (GPS), parseo de tramas NMEA y envío HTTP al servidor Java. |
| Lenguaje principal | Java 17 | Lenguaje maduro, multiplataforma, con amplio soporte y ecosistema. Java 17 es una versión LTS (Long Term Support), garantizando estabilidad a largo plazo. |
| Herramienta de construcción | Apache Maven | Gestión estandarizada de dependencias y ciclo de vida del proyecto. Facilita la compilación, pruebas y empaquetado. |
| Base de datos | SQLite (`sqlite-jdbc`) | Motor de base de datos embebido, sin necesidad de servidor separado. Ideal para entornos con recursos limitados y despliegue simplificado. |
| Persistencia | Bases de datos por dominio | Separación en `usuarios.db`, `auditorias.db` y `posiciones.db` para mayor modularidad y facilidad de mantenimiento. |
| Servidor web embebido | Jetty (embebido en Maven) | Permite ejecutar el servidor web directamente desde el proyecto sin instalaciones adicionales. |

### Frontend

| Componente | Tecnología | Justificación |
|------------|-----------|---------------|
| Estructura | HTML5 | Estándar web moderno con soporte universal en navegadores actuales. |
| Estilos | CSS3 | Permite diseño responsivo sin dependencia de frameworks externos. |
| Lógica del cliente | JavaScript vanilla | Sin dependencias de frameworks como React o Angular, reduciendo la complejidad del proyecto y el tamaño del bundle. |
| Visualización de mapas | Leaflet.js | Biblioteca open source, ligera y ampliamente documentada para mapas interactivos. Compatible con OpenStreetMap sin costos de licencia. |

### Diagrama de Capas (Representación)

```
┌──────────────────────────────────────────────────────┐
│         CAPA DE HARDWARE (Dispositivo en campo)      │
│  Módulo GPS NEO-6M → ESP32 (firmware) → Wi-Fi        │
│  Lee tramas NMEA, extrae lat/lon/timestamp            │
└────────────────────┬─────────────────────────────────┘
                     │ HTTP POST /api/posicion
┌────────────────────▼─────────────────────────────────┐
│              CLIENTE (Navegador)                     │
│   HTML5 + CSS3 + JavaScript + Leaflet.js             │
└────────────────────┬─────────────────────────────────┘
                     │ HTTP / REST
┌────────────────────▼─────────────────────────────────┐
│           SERVIDOR (Java 17)                         │
│        Jetty + Servlets + DAOs                       │
└────────────────────┬─────────────────────────────────┘
                     │ JDBC
┌────────────────────▼─────────────────────────────────┐
│         BASE DE DATOS (SQLite)                       │
│  usuarios.db | posiciones.db | auditorias.db         │
└──────────────────────────────────────────────────────┘
```

La incorporación del ESP32 como dispositivo emisor de posiciones convierte a
TrackVer A&A en un sistema con interconexión real entre hardware y software,
eliminando la necesidad de simular datos GPS durante las pruebas y validando
funcionalmente la arquitectura completa end-to-end.

## Usuarios Objetivo

TrackVer A&A está diseñado para tres perfiles de usuario con necesidades y
niveles de acceso diferenciados:

| Perfil | Rol en el sistema | Necesidades principales | Nivel técnico |
|--------|------------------|------------------------|---------------|
| **Administrador** | Gestión total del sistema | Alta del sistema, registro de usuarios y dispositivos, configuración general | Medio-alto |
| **Auditor** | Operación técnica | Monitoreo de dispositivos, activación, geocercas, comandos remotos | Medio |
| **Usuario** | Consulta de su flota | Visualizar posiciones, historial, alertas de sus vehículos | Básico |

Dado que los usuarios finales (propietarios de flotas) poseen conocimientos
técnicos básicos, la interfaz del sistema prioriza la usabilidad y la
simplicidad sobre la densidad de funcionalidades. La navegación está
estructurada por rol, de modo que cada usuario accede únicamente a las
funciones pertinentes a su perfil, reduciendo la curva de aprendizaje.

## Mercado Objetivo

El sistema está diseñado para empresas con flotas de entre 5 y 500 vehículos,
incluyendo empresas de transporte de carga, reparto local, logística regional y
propietarios de vehículos de uso comercial. Este rango de tamaño corresponde
al segmento de pequeñas y medianas empresas (PYME) del sector transporte en
México, que constituye la mayoría del parque vehicular comercial del país.

Según el INEGI (2023), el transporte de carga por carretera es uno de los
sectores más activos de la economía mexicana, con miles de unidades operando
en rutas locales y regionales. Sin embargo, el acceso a tecnología de rastreo
vehicular de calidad sigue siendo limitado para las PYME, principalmente por
los costos de las plataformas disponibles y la complejidad de su configuración.
TrackVer A&A se posiciona como una alternativa accesible y con soporte cercano
para este segmento desatendido.

### Casos de Uso Representativos

- **Empresa de reparto local:** 10 vehículos de entrega, necesita saber si las
  rutas asignadas se cumplen y si los vehículos salen de la zona de operación.
- **Transportista de carga regional:** 25 tractocamiones, requiere historial de
  recorridos para control interno y apagado remoto ante robo de unidad.
- **Servicio de transporte de personal:** 15 autobuses, necesita geocercas para
  verificar que las rutas de las paradas se respetan.
- **Empresa instaladora de GPS (caso de origen):** Más de 50 instalaciones
  mensuales, requiere activar dispositivos de forma autónoma sin depender de
  soporte de la empresa matriz.

## Supuestos del Proyecto

Los siguientes supuestos han sido considerados para la definición del alcance
y la planificación del proyecto:

1. Los dispositivos GPS utilizados en producción serán compatibles con el
   protocolo de comunicación implementado en el sistema.
2. El cliente final cuenta con acceso a internet para utilizar la plataforma web.
3. El servidor donde se desplegará el sistema tendrá Java 17 instalado y
   disponibilidad continua.
4. El informante clave (técnico instalador de GPS) estará disponible para
   validación de requerimientos y pruebas de aceptación durante el desarrollo.
5. Los datos de posición GPS se reciben en formato estándar (latitud, longitud,
   timestamp) compatible con el módulo de recepción del sistema.

## Factores Críticos de Éxito

Para que TrackVer A&A sea considerado exitoso al término del proyecto, deben
cumplirse los siguientes factores:

1. **Funcionalidad core operativa:** Los módulos de autenticación, visualización
   de mapa, historial de posiciones y geocercas deben estar completamente
   implementados y funcionales.
2. **Calidad del código:** El sistema debe contar con pruebas unitarias con
   cobertura mínima del 70% y no presentar vulnerabilidades de seguridad
   básicas (contraseñas en texto plano, acceso no autorizado por rol).
3. **Usabilidad:** Un usuario con conocimientos básicos debe poder operar el
   sistema sin entrenamiento extenso.
4. **Documentación:** El proyecto debe contar con manual de usuario, manual
   técnico y documentación del código fuente.
5. **Viabilidad comercial:** La arquitectura del sistema debe permitir su
   despliegue en un entorno de producción real con mínimos ajustes, validando
   su potencial como producto comercializable.

## Modelo de Negocio

Una vez concluido el desarrollo académico, TrackVer A&A podrá ser
comercializado bajo dos esquemas complementarios:

1. **Venta de producto (licencia perpetua):** El cliente adquiere el sistema
   una vez y lo instala en su propia infraestructura. Incluye soporte técnico
   inicial por un periodo determinado. Ideal para empresas con capacidad técnica
   interna y preferencia por control total de su información.

2. **Suscripción (SaaS):** Pago mensual o anual que incluye acceso a la
   plataforma alojada en servidores del proveedor, actualizaciones continuas y
   soporte técnico permanente. Este modelo, definido por Mell y Grance (2011)
   como Software como Servicio, permite al proveedor mantener el control de la
   plataforma mientras el cliente accede a ella a través de internet desde
   cualquier navegador, sin necesidad de instalaciones locales. Este esquema
   favorece la escalabilidad del negocio y garantiza ingresos recurrentes que
   permiten dar continuidad al desarrollo y soporte del sistema.

La estrategia inicial contempla ofrecer el modelo de suscripción con una tarifa
diferenciada según el número de vehículos activos, haciendo el producto accesible
para flotas pequeñas y escalable conforme el cliente crece.
